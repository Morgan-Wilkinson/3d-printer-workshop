# Price Monitor

**File:** `docs/pages/price-monitor.html` (~1,500 lines, self-contained)
**URL:** http://3dworkshop.local/pages/price-monitor.html
**Type:** API-backed application — price tracking and sale alerts
**Backend:** `http://price-api.local/api` (PostgreSQL, part of the home-server stack)

Tracks products you're interested in buying — filament, printer hardware, anything — and alerts when prices drop below your target. Unlike the other workshop apps, this one is **server-backed**: all product, history, and alert data lives in the home-server PostgreSQL database via the Price Monitor API. `localStorage` is used only for UI preference settings.

Related doc: [`live_updates_price_automation.md`](live_updates_price_automation.md) covers the automated price-fetch pipeline in depth.

---

## Views

Four tabs plus a stats header row.

| Tab | Purpose |
|---|---|
| **Watch List** | Card grid of tracked products with search and filter |
| **Alerts** | Price-drop/target alerts generated by the backend |
| **Price History** | Table of recorded price points per product |
| **Settings** | Alert preferences, check frequency, API info, export version |

### Stats header

- **Watching** — total products in the watch list
- **Below target** — products where `current_price ≤ target_price`
- **New alerts** — unread alert count
- **Avg drop (30d)** — mean percentage drop across products with ≥2 history points in the last 30 days

## Data model

Products are stored server-side; the frontend maps between its camelCase form fields and the API's snake_case fields.

### Product (API shape)

```js
{
  id: 1,
  name: "Bambu Lab PLA Basic 1kg",
  brand: "Bambu Lab",
  category: "PLA",            // form field is labeled "Category" (wMaterial)
  current_price: 22.99,
  target_price: 19.99,
  source: "Amazon",           // retailer
  url: "https://…",
  upc: "B0…",                 // product ID — auto-extracted from URL by backend
  notes: ""
}
```

### Price history entry

```js
{ id, product_id, price, fetch_time, source }
```

### Alert

```js
{ id, product_id, type, message, severity, created_at, read }
```

### Settings (localStorage only — `priceMonitorSettings`)

```js
{
  inApp: true,                // toast notifications
  browser: false,             // Notification API push
  email: false,
  emailAddress: "",
  frequency: "manual" | "hourly" | "daily" | "custom",
  customDays: 2               // when frequency === "custom"
}
```

## API surface

All calls go to `http://price-api.local/api`:

| Endpoint | Method | Purpose |
|---|---|---|
| `/products` | GET | List all watched products |
| `/products` | POST | Create product (backend extracts product ID from `url` if `upc` not given) |
| `/products/{id}` | PUT | Update product |
| `/products/{id}` | DELETE | Delete product |
| `/price-history/{id}?days=N\|all` | GET | Price history for one product |
| `/alerts` | GET | List alerts |
| `/alerts/clear` | POST | Clear all alerts |
| `/check-prices` | POST | Trigger an on-demand price fetch |
| `/settings/frequency` | POST | Set backend check frequency (`{frequency, customDays}`) |
| `/extract-id` | POST | Extract a product ID from a URL (`{url}` → `{extracted_id}`) |

If the API is unreachable, the app loads empty arrays and logs to console — every view shows its empty state rather than crashing.

## Feature details

### Watch list

- Cards show name, brand/category, current vs. target price, source, and a badge ("Below target" / "Watching").
- Actions per card: **Update price** (manual price entry with date + source), **Edit**, **History** (jumps to the History tab filtered to that product).
- Filters: free-text search (name, brand, category, source) and a dropdown — All / On sale / Price dropped / Below target. Note: "Price dropped" is currently a stub that matches nothing (see [Known limitations](#known-limitations)).

### Add/Edit modal

Fields: name (required), brand, category, current price, target price, retailer/source (datalist: Amazon, Walmart, Best Buy, Target, eBay, AliExpress, Bambu Lab Store, Elegoo Store, Micro Center, Prusa Store), product URL, notes.

**URL auto-extraction:** typing a URL fires `POST /extract-id`; supported retailers are Amazon, Bambu Lab, Walmart, Best Buy, Target, and eBay. On success the extracted ID populates a read-only field; the backend also attempts extraction on save if `upc` is empty.

### Price updates

"Update price" on a card opens a modal (new price, date, source) that PUTs the new `current_price`. The backend records a history entry and evaluates alert conditions.

### Alerts

Rendered from `/alerts` — title, message, timestamp. "Clear all alerts" POSTs `/alerts/clear` after confirmation. Notification delivery (`triggerNotifications`):

- **In-app** — toast popup
- **Browser** — `Notification` API (requests permission on enable)
- **Email** — placeholder only; logs the intended recipient to console (no email backend wired in the frontend)

### Check frequency

Settings → Check Frequency: Manual / Hourly / Daily / Custom N days. Saved to `localStorage` and pushed to `POST /settings/frequency` so the backend fetch job matches. "Check prices now" in Settings triggers `POST /check-prices`.

### Export / Import

- **Export** downloads `price-monitor-backup-YYYY-MM-DD.json` containing `watchList`, `alerts`, `settings`, `exportVersion: "2.0"`, `exportType: "api-based"`.
- **Import is not implemented** — `importData()` is a stub; restore by re-adding products (or restoring the Postgres backup on the server).

## Architecture notes

- `Store` is an async API client, not a local store: `init()` loads settings from `localStorage` then `loadFromAPI()` populates `watchList` and `alerts`. Every mutation re-fetches from the API.
- No build-plate/filament-domain coupling — despite the filament-oriented branding, products are generic (name/brand/category/source).
- Filament Log pushes products here automatically via its own price-API sync (`priceApiId` on each spool/refill) — see `filament-log.md`.

## Known limitations

- **"Price dropped" filter is a no-op** — `matchesFilter = false` with a comment noting it needs an async history check.
- **"All products" history view is empty** — per-product fetch only; the aggregate path returns `[]`.
- **"Change (7d)" column always shows "—"** — computed values aren't wired into the card render.
- **History "Change" column is blank** — `change`/`changeClass` are declared but never computed.
- **Email alerts are a stub** — the checkbox persists but only `console.log`s.
- **No authentication** — the API is trusted on the LAN; anyone on the network can modify the watch list.
- Deleting a product presumably cascades history server-side; the frontend doesn't warn about history loss.
